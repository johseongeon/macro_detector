행동 기반 매크로 탐지 보안 브라우저

콘서트·대중교통 예매 사이트 전용 데스크톱 브라우저(.exe). WebAssembly로 마우스·키보드 행동을 수집하고 분석해 사용자별 신뢰도 점수(Trust Score)를 실시간으로 산출합니다. 판단은 정확하게, 지연은 최소로 하는 것이 목표입니다.

01배경 및 목표

인기 공연과 명절 승차권 예매 때는 매크로(자동 클릭, 스크립트, 브라우저 자동화 도구)가 정상 사용자의 기회를 빼앗습니다. 기존 CAPTCHA는 모든 사용자에게 불편을 주고, 최근에는 AI 기반 풀이 서비스로 쉽게 우회됩니다. 이 프로젝트는 사용자가 직접 실행하는 전용 브라우저 안에서 행동 신호를 수집합니다. 그래서 대부분의 정상 사용자는 아무런 추가 절차 없이 통과하고, 매크로만 걸러낼 수 있습니다.

범위

  • 포함: Windows용 전용 브라우저(.exe), WASM 수집·분석 모듈, 온디바이스 점수 산출, 서버 측 검증 API, 예매 사이트용 연동 SDK, 운영 대시보드
  • 제외(1차): macOS/모바일 지원, 결제 사기 탐지, 계정 도용 탐지(추후 확장 가능)

02핵심 설계 원칙

① 오판 최소화 (False Positive ↓)

  • 모델 하나만으로 차단하지 않습니다. 독립적인 신호가 여러 개 일치할 때만 차단합니다.
  • 판단이 애매하면 차단하지 않고 단계적으로 확인합니다(추가 신호 수집 → 간단한 확인 → 차단).
  • 점수는 보정(calibration)을 거쳐 실제 확률에 가깝게 만듭니다. 임계값은 목표 FPR을 기준으로 정합니다.
  • 접근성 사용자(키보드만 쓰는 사용자, 스크린리더 사용자), 고령자, 터치패드 사용자를 별도 집단으로 나눠 검증합니다.

② 최저 지연 (Latency ↓)

  • 점수는 사용자 PC에서(온디바이스) 미리 계산합니다. 예매 버튼을 누를 때 따로 분석을 시작하지 않습니다.
  • 이벤트가 들어올 때마다 특징값을 증분 갱신(O(1))합니다. 원본 시퀀스를 다시 처리하지 않습니다.
  • 서버는 서명된 토큰만 검증합니다. 무거운 모델은 회색 구간 사용자에게만 비동기로 실행합니다.
  • 수집 경로에는 메모리 할당이 없는 링버퍼를 쓰고, 분석은 메인 스레드가 아닌 Worker에서 실행합니다.
두 목표가 충돌하면 오판 최소화가 우선입니다. 지연은 아키텍처로 해결할 수 있지만, 정상 사용자를 잘못 차단하면 신뢰를 되돌릴 수 없습니다. 그래서 빠른 경로(Fast path)는 "명확한 정상"과 "명확한 매크로"만 바로 판정하고, 애매한 경우는 느리더라도 정밀한 경로로 보냅니다.

03시스템 아키텍처

동작 흐름

  1. 사용자가 전용 브라우저를 실행하고 예매 사이트에 접속합니다. 접속하는 순간부터 수집이 시작됩니다.
  2. 네이티브 계층은 OS 수준 입력(Raw Input)을, WebView 계층은 DOM 이벤트를 받아 WASM 링버퍼에 기록합니다.
  3. WASM Collector가 이벤트마다 특징값을 증분 갱신하고, Worker의 Scorer가 주기적으로(예: 200ms마다, 혹은 중요 이벤트 직후) 점수를 갱신합니다.
  4. '예매' 같은 보호 대상 행동이 발생하면, 이미 계산된 점수를 서명된 토큰으로 첨부해 요청합니다. 추가 계산은 없습니다.
  5. 서버는 토큰을 빠르게 검증해 허용/확인/차단을 결정합니다. 회색 구간이면 Deep Analyzer가 비동기로 정밀 분석합니다.

04데이터 수집 (WASM Collector)

계층수집 대상주요 목적비고
Native (Win32)Raw Input(WM_INPUT), Low-level hook의 LLMHF_INJECTED / LLKHF_INJECTED 플래그, 입력 장치 핸들SendInput 등으로 주입된 합성 입력 탐지매우 강한 신호이며, 오판 가능성이 낮음
WebViewpointermove/down/up, wheel, keydown/up(코드 종류만), focus/blur, visibilitychange, isTrusted, 이벤트 타임스탬프궤적·리듬 등 행동 패턴 분석getCoalescedEvents()로 고해상도 궤적 확보
Environment가상 머신 흔적, 디버거 연결, 원격 데스크톱 세션, 자동화 프레임워크 흔적, 다중 인스턴스 실행 여부실행 환경의 위험도 평가단독으로 차단하지 않고 가중치로만 반영

수집 파이프라인 설계

  • 고정 크기 링버퍼: 이벤트를 16~24바이트 고정 레코드(type, t_µs, x, y, extra)로 저장합니다. 런타임 메모리 할당이 없습니다.
  • SharedArrayBuffer + Atomics: 메인 스레드는 쓰기만 하고, 분석 Worker가 읽습니다. 그래서 UI 스레드에 지연이 생기지 않습니다.
  • Passive 리스너: 모든 리스너를 { passive: true }로 등록해 스크롤과 렌더링 성능에 영향이 없게 합니다.
  • 단조 증가 시계: performance.now()와 네이티브 QPC 타임스탬프를 같이 기록해 타이밍 조작을 교차 검증합니다.

05특징(Feature) 설계

모든 특징은 슬라이딩 윈도우 기반 증분 통계(Welford 평균·분산, 고정 bin 히스토그램, EWMA)로 계산합니다. 이벤트 한 건당 처리 비용은 일정합니다.

분류특징사람 vs 매크로
마우스 궤적속도·가속도·저크(jerk) 분포, 곡률, 경로 효율(직선거리/실제거리), 방향 전환 횟수사람은 종 모양 속도 곡선과 미세한 떨림이 있습니다. 매크로는 직선 경로, 일정한 속도, 또는 지나치게 매끈한 베지어 곡선을 보입니다.
목표 도달Fitts' law 적합도, 오버슈트·보정 동작, 클릭 전 감속 구간, 클릭 위치의 버튼 내 분포사람은 목표 근처에서 감속하고 보정합니다. 매크로는 정확히 중앙을 누르거나 지나치게 고른 분포를 보입니다.
클릭mousedown→up 유지 시간, 클릭 간 간격의 분산·엔트로피, 이동 없는 클릭 비율매크로는 간격 분산이 매우 작거나 인위적인 균등 난수 분포를 보입니다.
키보드Dwell time(누름 유지), Flight time(키 간 이동), 다이그래프 타이밍 분포, 동시 누름(rollover) 비율사람은 키 조합마다 고유한 리듬을 보입니다. 매크로는 일정한 리듬이거나 rollover가 없습니다.
타이밍이벤트 간격 지터, 폴링 주기 정합성(125/500/1000Hz), 페이지 로드→첫 행동 반응 시간사람이 시각 자극에 반응하는 데는 보통 150ms 이상 걸립니다. 실제 장치 폴링 주기와 맞지 않는 이벤트는 의심 대상입니다.
무결성주입 플래그, isTrusted=false 비율, Native–DOM 이벤트 불일치, 정수 좌표만 나오는 현상강한 신호입니다(Stage 1 규칙에 사용).
세션 맥락예매 오픈 전 체류 시간, 페이지 탐색 패턴, 포커스 이탈 횟수보조 신호로만 사용합니다.

06탐지 모델 및 점수 산출

탐지는 3단계 계층 구조입니다. 앞 단계일수록 빠르고 확실한 경우만 판정하고, 애매한 경우는 다음 단계로 넘깁니다.

단계위치방법지연역할
Stage 1 규칙Client WASM결정적 규칙: 주입 입력, isTrusted=false, 물리적으로 불가능한 반응 시간 등< 0.1ms명백한 매크로를 즉시 확정합니다. 규칙마다 FPR을 검증한 뒤에만 배포합니다.
Stage 2 GBDTClient WASM집계 특징 약 60~120개를 입력으로 하는 경량 Gradient Boosted Trees(트리 200개 이하)< 1ms대부분의 사용자를 판정합니다. 결과는 보정된 확률로 출력합니다.
Stage 3 시퀀스Server원시 궤적 기반 1D-CNN/GRU와 교차 세션 그래프 분석수십~수백 ms (비동기)회색 구간만 분석합니다. 사전 대기열 단계에서 실행해 사용자가 지연을 느끼지 않게 합니다.

신뢰도 점수 → 조치 매핑

80–100신뢰

추가 절차 없이 즉시 통과합니다. 정상 사용자 대부분이 여기에 해당해야 합니다.

50–79관찰

통과시키되 신호를 더 수집하고, Stage 3를 비동기로 실행합니다.

20–49확인

가벼운 상호작용 확인(드래그 등)을 요청합니다. 차단하지 않습니다.

0–19차단

Stage 1 규칙에 걸렸거나, 독립 신호 2개 이상이 일치할 때만 차단합니다.

※ 구간 경계값은 예시입니다. 실제 값은 검증 데이터에서 목표 FPR을 만족하도록 정합니다(7장 참고).

07오판 최소화 전략

모델 측면

  • FPR 우선 임계값: ROC 전체 성능보다 "FPR 0.1%일 때의 TPR"을 핵심 지표로 삼습니다.
  • 확률 보정: Isotonic regression으로 점수를 실제 확률에 맞춥니다. 보정 오차(ECE)를 지속적으로 감시합니다.
  • 판정 보류(Abstention): Conformal prediction으로 불확실성이 큰 샘플은 판정하지 않고 다음 단계로 넘깁니다.
  • 최소 증거량: 이벤트 수가 기준(예: 마우스 이동 300개 이상)에 못 미치면 낮은 점수를 주지 않고 '관찰' 상태로 둡니다.
  • 앙상블 합의: 차단은 규칙 기반과 학습 기반처럼 서로 독립적인 탐지기가 함께 동의할 때만 실행합니다.

운영 측면

  • 집단별 검증: 터치패드, 트랙볼, 펜 태블릿, 키보드 전용, 스크린리더, 고령자, 운동 장애 사용자 집단마다 FPR 상한을 따로 둡니다.
  • Shadow 모드: 새 모델은 최소 2주 동안 판정만 기록하고 실제 조치는 하지 않습니다. 오판율을 확인한 뒤 적용합니다.
  • 점진 배포: 1% → 10% → 50% → 100%로 확대하고, 지표가 나빠지면 자동으로 롤백합니다.
  • 이의 제기 경로: 차단된 사용자가 즉시 대체 인증(본인 인증 등)으로 구제받을 수 있게 합니다. 이 사례는 라벨로 다시 학습에 반영합니다.
  • 설명 가능성: 판정마다 상위 기여 특징(SHAP)을 기록해 운영자가 오판 원인을 추적할 수 있게 합니다.
드리프트 주의: OS 업데이트, 새 마우스 드라이버, 고주사율 모니터처럼 정상 환경이 바뀌어도 오판이 늘어날 수 있습니다. 집단별 점수 분포를 매일 감시하고, 분포가 크게 바뀌면(PSI > 0.2) 알림을 보냅니다.

08지연 시간 최소화 전략

구간예산기법
이벤트 수집 (메인 스레드)< 5µs / event링버퍼에 쓰기만 합니다. 메모리 할당과 JS↔WASM 경계 호출을 최소화합니다(배치 처리).
특징 갱신 (Worker)< 50µs / event증분 통계, SIMD(wasm simd128), 고정 크기 배열을 사용합니다.
점수 산출 (Worker)< 1ms트리를 평탄화해 캐시 친화적인 배열로 순회합니다. 결과를 미리 계산해 캐시해 둡니다.
토큰 생성< 0.5msEd25519 서명을 사용합니다. 점수 갱신 시점에 미리 서명해 둡니다.
서버 검증 (Fast path)p99 < 5ms상태 없는 서명 검증과 nonce 확인(Redis/인메모리)을 합니다. 별도 모델 추론은 없습니다.
예매 클릭 → 판정 완료p99 < 10ms (네트워크 제외)클릭 시점에 새로 계산하지 않고 미리 준비된 토큰을 첨부합니다.

Stage 3 정밀 분석은 예매 오픈 전 대기열 진입 단계에서 미리 실행합니다. 그래야 실제 예매 순간에 지연이 생기지 않습니다. 정밀 분석이 끝나지 않았다면 Stage 2 결과로 판정하고, 결과는 나중에 반영합니다(예: 결제 단계에서 재확인).

09보안 · 위변조 방지

클라이언트 쪽 판정은 원칙적으로 신뢰할 수 없습니다. 그래서 "클라이언트는 빠르게 판정하고, 서버는 검증한다"는 원칙으로 설계합니다.

  • 토큰 구성: 점수 + 특징 요약 벡터 + 서버 발급 nonce + 타임스탬프 + 바이너리 해시. 서버는 특징 요약으로 점수를 다시 계산해 일치하는지 표본 검사합니다.
  • 키 보호: 디바이스 키는 TPM/Windows CNG에 저장하고, 설치할 때 서버에 등록합니다. 세션마다 단기 키를 파생합니다.
  • 바이너리 무결성: 코드 서명, 실행 중 자체 해시 검사, WASM 모듈 해시 검증, 난독화(제어 흐름 평탄화)를 적용합니다.
  • 디버깅·자동화 차단: WebView의 원격 디버깅 포트와 DevTools를 비활성화하고, 자동화 프로토콜 연결을 막습니다.
  • 모델 갱신: 탐지 모델과 규칙은 서명된 패키지로 원격 배포합니다. 공격자가 우회책을 학습하기 전에 빠르게 교체할 수 있습니다.
  • 서버 측 교차 신호: 같은 디바이스·IP 대역의 동시 세션 수, 같은 행동 지문의 반복처럼 클라이언트가 숨길 수 없는 신호를 함께 사용합니다.

10개인정보 보호

  • 입력 내용 미수집: 키보드는 키 종류 범주(문자/숫자/기능키)와 타이밍만 기록합니다. 실제 입력 문자는 절대 저장하거나 전송하지 않습니다.
  • 데이터 최소화: 서버에는 집계된 특징 요약만 보냅니다. 원시 궤적은 회색 구간일 때만, 그리고 짧은 기간만 보관합니다(예: 7일).
  • 보호 대상 페이지에서만 수집: 수집은 연동된 예매 사이트 도메인에서만 동작합니다.
  • 법적 준수: 개인정보보호법(PIPA)에 따른 수집 목적·항목·보관 기간을 고지하고 동의를 받습니다. 행동 지문이 개인식별정보에 해당하는지 법률 검토를 받습니다.

12평가 지표 및 검증

정확도 지표

  • FPR @ 차단 임계값 (전체 + 집단별) — 최우선 지표
  • TPR @ FPR 0.1% / 0.01%
  • 추가 인증 요구율 (정상 사용자 기준)
  • 보정 오차 ECE, Brier score
  • 매크로 유형별 탐지율 (단순 클릭 / 자동화 브라우저 / 사람 흉내 / 원격 조작)

성능 지표

  • 클릭 → 판정 지연 p50 / p99 / p99.9
  • 이벤트당 처리 시간, Worker CPU 점유율
  • 입력 지연 증가량 (수집 기능 켬/끔 비교, INP)
  • 메모리 사용량, 설치 파일 크기
  • 서버 Verify API 처리량(RPS) 및 꼬리 지연

데이터셋 계획

  • 정상 데이터: 베타 테스터 모집(목표 1,000명 이상, 다양한 연령·장치 포함), 모의 예매 시나리오 수행
  • 매크로 데이터: 레드팀이 난이도별 매크로를 제작합니다(Level 1 단순 반복 → Level 4 사람 궤적을 재생하거나 생성 모델을 쓰는 매크로).
  • 분할 원칙: 사용자 단위로 학습/검증/테스트를 나눠 데이터 누수를 막습니다. 테스트셋에는 학습에 쓰지 않은 매크로 도구를 반드시 포함합니다.
